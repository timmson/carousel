# Задача: разработка веб-приложения «Кто ведёт протокол?»

Ты — опытный Frontend-разработчик и UI/UX-дизайнер. Твоя задача — самостоятельно разработать полностью работающее одностраничное веб-приложение для выбора участника встречи, ответственного за фиксацию договорённостей и ведение протокола.

Приложение должно быть статическим, работать непосредственно в браузере и размещаться на GitHub Pages.

## 1. Основная идея

Пользователь вставляет список участников встречи, скопированный из Microsoft Outlook. Приложение автоматически извлекает ФИО и адреса электронной почты, отображает участников в редактируемой таблице и размещает их имена на колесе случайного выбора.

После нажатия кнопки «Крутить» колесо начинает вращаться, постепенно замедляется и останавливается на случайно выбранном участнике.

Выбранный участник становится ответственным за ведение протокола встречи.

## 2. Функциональные требования

### 2.1. Ввод участников

В верхней части страницы разместить блок «Участники встречи».

Добавить многострочное текстовое поле с возможностью вставки списка участников из Outlook.

Пример входных данных:

ФИО 1 <email_1@example.com>; ФИО 2 <email_2@example.com>; ФИО 3 <email_3@example.com>

Требования:
- Поддерживать формат Outlook: `ФИО <email>; ФИО <email>`.
- Поддерживать разделители в виде точки с запятой, запятой и переносов строк, если они не находятся внутри адреса или имени.
- Извлекать ФИО и email отдельно.
- Корректно обрабатывать пробелы и лишние разделители.
- Не добавлять пустые записи.
- Исключать дубликаты по email.
- Не ломаться, если часть записей не содержит email.
- После вставки списка предоставить кнопку «Загрузить участников».

### 2.2. Таблица участников

После обработки списка автоматически заполнить таблицу со столбцами:

| № | ФИО | Email | Действие |
|---|---|---|---|

Функции таблицы:
- Редактирование ФИО непосредственно в таблице.
- Редактирование email.
- Удаление отдельного участника.
- Добавление нового участника вручную.
- Автоматическая перенумерация строк.
- Изменения в таблице должны сразу отражаться на колесе.
- Если участник удалён, его имя должно исчезнуть с колеса.
- Если участник добавлен, его имя должно появиться на колесе.

Предусмотреть возможность очистить весь список.

### 2.3. Колесо случайного выбора

Основной визуальный элемент приложения — большое интерактивное колесо с секторами.

Требования:
- Каждый участник занимает один сектор.
- В каждом секторе отображается ФИО участника.
- Сектора имеют разные контрастные цвета.
- Имена должны оставаться читаемыми.
- Цвета распределяются автоматически.
- Колесо должно корректно отображать как небольшое количество участников (2–3), так и большое (20–30).
- Колесо должно адаптироваться к размеру экрана.
- Над колесом или сбоку разместить неподвижную стрелку-указатель.
- В центре колеса разместить декоративную кнопку или эмблему.

Для реализации можно использовать SVG или Canvas. Предпочтительно SVG, если это позволяет обеспечить хорошую читаемость и чёткость изображения.

### 2.4. Механика вращения

Под колесом разместить большую заметную кнопку:

**«КРУТИТЬ!»**

При нажатии:
1. Запускается анимация вращения колеса.
2. Колесо совершает несколько полных оборотов.
3. Скорость постепенно снижается.
4. Колесо плавно останавливается на случайном секторе.
5. Стрелка указывает на выбранного участника.
6. Выбранный участник определяется программно, а не визуально.

Технические требования:
- Использовать генератор случайных чисел.
- Выбор должен быть равновероятным для всех участников.
- Предпочтительно использовать `crypto.getRandomValues()` для получения случайного индекса.
- Исключить возможность повторного запуска вращения до завершения текущей анимации.
- На время вращения заблокировать изменение списка участников.
- Продолжительность вращения ориентировочно 4–6 секунд.
- Предусмотреть плавное замедление (ease-out).
- Убедиться, что выбранный сектор действительно совпадает с положением стрелки после завершения вращения.

### 2.5. Результат выбора

После остановки колеса показать отдельный выразительный блок:

**Сегодня протокол ведёт:**

ФИО выбранного участника

При наличии email дополнительно показать его адрес.

Добавить праздничную анимацию появления результата (например, конфетти).

Результат должен быть хорошо заметен и не теряться среди остальных элементов страницы.

Добавить кнопку «Крутить ещё раз», позволяющую выполнить новый выбор.

После повторного запуска старый результат заменяется новым.

## 3. Дизайн и пользовательский интерфейс

Создай современный, аккуратный и визуально привлекательный интерфейс.

Стиль:
- Современное корпоративное веб-приложение.
- Светлый фон.
- Минималистичный дизайн.
- Аккуратные карточки с небольшим скруглением.
- Мягкие тени.
- Хорошая типографика.
- Контрастные акцентные цвета.
- Плавные анимации.

Структура страницы:

1. Заголовок: «Кто ведёт протокол?»
2. Подзаголовок: «Справедливый выбор ответственного за договорённости на встрече».
3. Блок вставки участников.
4. Таблица участников.
5. Большое колесо случайного выбора.
6. Кнопка «КРУТИТЬ!».
7. Блок с результатом.

На широких экранах таблицу и колесо можно расположить в две колонки, если это не ухудшает восприятие. На мобильных устройствах все элементы должны располагаться вертикально.

Интерфейс должен быть полностью на русском языке.

## 4. Логика и ограничения

- Приложение работает полностью на стороне клиента.
- Не использовать backend и серверную базу данных.
- Не требовать авторизации.
- Не отправлять ФИО и email участников на внешние серверы.
- Не использовать внешние API.
- Не требовать регистрации.
- Не сохранять персональные данные в localStorage или других постоянных хранилищах.
- Не использовать платные библиотеки и сервисы.
- Все основные функции должны работать без интернета после загрузки приложения.

Если участников меньше двух, кнопка вращения должна быть неактивной, а пользователь должен увидеть понятное сообщение.

Если список пуст, показывать инструкцию по добавлению участников.

Если ФИО отсутствует, использовать email в качестве отображаемого имени.

## 5. Технический стек

Предпочтительный стек:
- React.
- TypeScript.
- Vite.
- CSS или CSS Modules.
- SVG для реализации колеса.

Использовать современные стабильные версии зависимостей.

Не перегружать проект сторонними библиотеками. Для конфетти можно использовать лёгкую библиотеку либо реализовать простую анимацию самостоятельно.

## 6. Подготовка к GitHub Pages

Приложение должно быть готово к публикации на GitHub Pages.

Необходимо:
- Настроить Vite для работы в GitHub Pages.
- Учесть публикацию сайта в подпапке репозитория, а не только в корне домена.
- Подготовить `vite.config.ts` с корректным `base`.
- Добавить GitHub Actions workflow для автоматической сборки и публикации при push в основную ветку.
- Убедиться, что все ресурсы загружаются с корректными путями.
- Не использовать серверную маршрутизацию.

Перед завершением работы обязательно:

1. Проверить корректность разбора данных Outlook.
2. Проверить добавление, редактирование и удаление участников.
3. Проверить синхронизацию таблицы и колеса.
4. Проверить случайность выбора.
5. Проверить совпадение результата с сектором под стрелкой.
6. Проверить блокировку повторного вращения.
7. Проверить поведение при 2, 3, 10, 20 и 30 участниках.
8. Проверить адаптивность на мобильных устройствах.
9. Проверить сборку production-версии.
10. Проверить корректность конфигурации GitHub Pages.

Исправить все обнаруженные ошибки.

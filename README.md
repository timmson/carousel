# Кто ведёт протокол?

Одностраничное веб-приложение для честного выбора участника встречи,
ответственного за ведение протокола. Вставьте список участников, скопированный
из Microsoft Outlook, — приложение разберёт ФИО и адреса, построит редактируемую
таблицу и колесо случайного выбора.

## Возможности

- Разбор формата Outlook `ФИО <email>` с разделителями `;`, `,` и переводами строк.
- Drag & drop `.msg` файла из Outlook — адресаты (К и Копия) извлекаются из письма прямо в браузере.
- Дедупликация по email, игнорирование пустых записей, устойчивость к ФИО вида «Иванов, И. И.».
- Редактируемая таблица: изменение ФИО, удаление, ручное добавление, очистка, авто-перенумерация.
- SVG-колесо с читаемыми подписями, автоматически подобранной палитрой и адаптивным размером.
- Вращение запускается кликом по колесу: 4–6 секунд с плавным замедлением, равновероятный выбор через `crypto.getRandomValues()`.
- Блок результата с конфетти и кнопкой «Крутить ещё раз».
- Полностью клиентская работа: без бэкенда, без внешних API, без сохранения данных.

## Технологии

React 19, TypeScript, Vite, CSS Modules, SVG. Конфетти реализованы вручную на
Canvas. Единственная сторонняя библиотека — `@npeersab/msgreader` для чтения
`.msg`: она подгружается лениво (отдельным чанком) и только когда вы действительно
перетаскиваете файл, так что обычная загрузка страницы остаётся лёгкой.

## Локальный запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev        # http://localhost:5173/carousel/
```

Другие команды:

```bash
npm run build      # проверка типов + production-сборка в dist/
npm run preview    # локальный просмотр собранной версии
npm test           # модульные тесты (разбор Outlook, геометрия колеса, рандом)
npm run typecheck  # только проверка типов
```

## Публикация на GitHub Pages

Приложение публикуется в подпапку репозитория, поэтому `base` в `vite.config.ts`
вычисляется автоматически:

1. `VITE_BASE` (если задан), иначе
2. `GITHUB_REPOSITORY` из окружения GitHub Actions (например `timmson/carousel` → `/carousel/`), иначе
3. `/carousel/` по умолчанию.

Готовый workflow лежит в `.github/workflows/deploy.yml`: при push в `main` он
ставит зависимости, прогоняет тесты, собирает проект и публикует `dist/` в Pages.

Чтобы включить деплой:

1. В настройках репозитория **Settings → Pages → Source** выберите **GitHub Actions**.
2. Сделайте push в ветку `main`.
3. Сайт появится на `https://<владелец>.github.io/carousel/`.

Если репозиторий будет переименован или опубликован в корне домена,
переопределите путь переменной `VITE_BASE` в workflow (например, `VITE_BASE: '/'`).

## Структура

```
src/
  components/   Header, ParticipantInput, ParticipantTable, Wheel, ResultCard, MsgDropper
  hooks/        useParticipants (список), useSpin (вращение и выбор)
  lib/          parseParticipants, wheel (геометрия), random, confetti, display
  __tests__/    модульные тесты
```

## Структура состояния

Идентификаторы участников не зависят от ФИО и email, поэтому редактирование
таблицы не пересоздаёт секторы колеса и не теряет фокус в полях ввода. Колесо и
выбор используют один и тот же отфильтрованный список, так что таблица и секторы
всегда синхронны.

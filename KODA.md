# KODA.md — контекст проекта «Кто ведёт протокол?»

## Обзор проекта

Одностраничное веб-приложение (SPA) для честного и наглядного выбора участника
встречи, который будет вести протокол. Пользователь вставляет список адресатов,
скопированный из Microsoft Outlook, приложение разбирает его в редактируемую
таблицу, строит SVG-«колесо фортуны» и по клику крутит его, выдавая победителя
с конфетти.

Ключевые свойства:

- **Полностью клиентское приложение.** Нет бэкенда, внешних API и сохранения
  данных — всё считается в браузере, ничего не покидает компьютер пользователя.
- **Разбор формата Outlook** `ФИО <email>` с разделителями `;`, `,` и переводами
  строк; дедупликация по email (или по ФИО, если адреса нет), устойчивость к
  ФИО вида «Иванов, И. И.».
- **Честный выбор.** Победитель определяется через `crypto.getRandomValues()`
  с rejection sampling (без modulo bias), угол остановки подбирается так, чтобы
  выбранный сектор гарантированно встал под стрелку.
- **Минимум зависимостей.** Сторонних библиотек в рантайме нет: конфетти
  нарисованы вручную на Canvas, колесо — на чистом SVG.

### Технологический стек

| Слой        | Технология                                        |
| ----------- | ------------------------------------------------- |
| UI          | React 19 (только хуки, без классов)               |
| Язык        | TypeScript 7, режим `strict`                      |
| Сборка      | Vite 8, таргет `es2022`                           |
| Стили       | CSS Modules (`.module.css`) + `src/index.css`     |
| Графика     | SVG (колесо), Canvas (конфетти)                   |
| Тесты       | Vitest 5                                          |
| Деплой      | GitHub Pages через GitHub Actions                 |

### Архитектура

Одностраничник с восходящим потоком состояния: весь стейт живёт в `App.tsx` и
двух хуках, компоненты презентационные и получают данные/колбэки пропсами.

```
src/
  main.tsx                 точка входа, монтирование <App /> в #root
  App.tsx                  композиция трёх колонок + состояние текста ввода
  types.ts                 Participant { id, name, email }, ParsedParticipant
  components/              Header, ParticipantInput, ParticipantTable,
                           Wheel, ResultCard (каждый + свой *.module.css)
  hooks/
    useParticipants.ts     CRUD-операции над списком участников
    useSpin.ts             фазы простоя/вращения, угол, победитель, ошибки
  lib/
    parseParticipants.ts   разбор текста Outlook на записи
    wheel.ts               геометрия колеса: углы секторов, палитра
    random.ts              crypto-рандом: randomInt / randomFloat
    confetti.ts            конфетти на Canvas
    display.ts             displayName / truncate — подписи секторов
  __tests__/               unit.test.ts, spinGeometry.test.ts, render.test.tsx
```

Важные инварианты (не ломать при правках):

1. **`id` участника не зависит от `name`/`email`.** Он генерируется один раз
   (`crypto.randomUUID()`), поэтому редактирование таблицы не пересоздаёт
   секторы колеса и не теряет фокус в полях ввода.
2. **Колесо и выбор используют один и тот же отфильтрованный список** —
   `wheelParticipants` в `App.tsx` (строки без имени и email отбрасываются).
   Таблица и секторы всегда синхронны.
3. **Победитель выбирается до анимации**, а угол считается в
   `computeTargetRotation`. Отсчёт угла — градусы по часовой стрелке от
   направления «вверх», туда же смотрит стрелка.
4. **Минимум два участника** для запуска вращения; иначе показывается
   предупреждение, а не ошибка рендера.
5. `finish()` вызывается и по `transitionend`, и по таймеру-страховке
   (`SPIN_DURATION_MS + FINISH_GRACE_MS`) — на случай фоновой вкладки или
   `prefers-reduced-motion`.

## Сборка и запуск

Требуется Node.js 20 или новее (в CI — 22). Все команды объявлены в
`package.json` → `scripts`:

```bash
npm install        # установка зависимостей
npm run dev        # dev-сервер: http://localhost:5173/carousel/
npm run build      # tsc --noEmit + production-сборка в dist/
npm run preview    # локальный просмотр собранной версии
npm test           # модульные тесты, однократный прогон (vitest run)
npm run test:watch # тесты в режиме наблюдения
npm run typecheck  # только проверка типов
```

Перед коммитом минимально достаточная проверка: `npm run typecheck && npm test`.
Полная — `npm run build` (она сама включает проверку типов).

### Публикация на GitHub Pages

- `base` в `vite.config.ts` вычисляется функцией `resolveBase()`:
  `VITE_BASE` → иначе из `GITHUB_REPOSITORY` (например `timmson/carousel` →
  `/carousel/`) → иначе `/carousel/` по умолчанию.
- Workflow `.github/workflows/deploy.yml`: push в `main` (или ручной запуск) →
  `npm ci` → `npm test` → `npm run build` (с `VITE_BASE: '/carousel/'`) →
  публикация `dist/`.
- В настройках репозитория должен быть выбран источник **Settings → Pages →
  Source → GitHub Actions**.
- При переименовании репозитория или публикации в корне домена переопределить
  `VITE_BASE` в workflow.

## Правила разработки

### Стиль кода

- Только функциональные компоненты на хуках; экспорт — именованный
  (`export function App()`), без default-экспортов.
- TypeScript в `strict` + `noUnusedLocals`, `noUnusedParameters`,
  `noFallthroughCasesInSwitch`, `isolatedModules`, `verbatimModuleSyntax`.
  Типы импортировать отдельно: `import type { Participant } from '../types'`.
- Строгая типизация публичных API хуков и модулей: описывать интерфейс
  результата (`ParticipantsApi`, `SpinApi`, `LoadResult`) и экспортировать его.
- Кавычки — одинарные, завершающая запятая в многострочных списках,
  отступ 2 пробела, длина строк ориентировочно до 100 символов.
- Комментарии на русском языке, объясняют *зачем* и *почему* (например, почему
  запятая не всегда разделитель), а не *что* делает код. Не переписывать
  существующие комментарии вне правимого блока.
- Весь пользовательский текст, UI и документация — на русском; `index.html`
  содержит `lang="ru"`.
- Стили — только через CSS Modules: файл `Component.module.css` рядом с
  `Component.tsx`, импорт `import styles from './Component.module.css'`,
  классы `styles.cardTitle`. Инлайн-стили не использовать.
- Чистые вычисления выносить в `src/lib/` как чистые функции — их проще тестировать
  и переиспользовать; компоненты не должны считать геометрию или парсить текст.
- Доступность: `aria-labelledby` у секций, `role="alert"` для сообщений об
  ошибках, колесо запускается кликом по нему.

### Тестирование

- Фреймворк — Vitest; тесты лежат в `src/__tests__/`, нейминг существующих
  файлов: `unit.test.ts` (разбор Outlook, display), `spinGeometry.test.ts`
  (углы, сектор под стрелкой, палитра), `render.test.tsx` (рендер через
  `renderToStaticMarkup` из `react-dom/server`).
- Подход: тестировать чистые функции и крайние случаи (2, 3, 10, 20, 30
  участников, пустые и битые записи, отсутствие уникальности цветов), а не
  детали DOM-структуры.
- Случайность не «мокать» нагло: функции рандома принимаются параметром
  (`random: () => number` в `computeTargetRotation`), что и использовать в
  тестах детерминированности.
- Любая правка геометрии колеса, парсера или рандома обязана сопровождаться
  обновлением/добавлением тестов — эти модули критичны для честности выбора.

### Практические ограничения

- Не добавлять рантайм-зависимости без крайней необходимости: осознанное
  решение проекта — ноль библиотек в продакшен-бандле.
- Не вводить персистентность (localStorage, запросы на сервер) — это ломает
  декларированную приватность приложения.
- Любые новые внешние пути/ресурсы должны учитывать сборку в подпапку
  (`base`), относительные пути в ассетах — через `import.meta.env.BASE_URL`.
